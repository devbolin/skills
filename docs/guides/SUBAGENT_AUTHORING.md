# Subagent 编写与协作指南

## 一、适用范围
本文档说明如何在 Skill 体系中设计、配置和使用 Subagent。

目标：
- 让 Subagent 委托边界可控
- 降低主流程上下文污染
- 保证可审计、可回退、可复用

## 二、什么是 Subagent
Subagent 是在独立上下文中执行特定任务的专业化代理。

典型特性：
- 独立 system prompt
- 独立上下文窗口
- 可配置模型与能力
- 可限制工具权限
- 可配置生命周期钩子（如 `onStart`/`onEnd`）

## 三、何时使用 Subagent
推荐使用：
- 任务可清晰切分且边界稳定（如代码审查、文档规范化）
- 主流程需要并行化处理多个子任务
- 需要隔离高噪声上下文（大日志、长报告）

不推荐使用：
- 子任务与主流程强耦合且需要频繁往返确认
- 任务规模太小，委托成本高于直接处理
- 委托边界无法定义，容易反复升级问题

## 四、最小配置模板

```json
{
  "subagents": {
    "code-reviewer": {
      "description": "发现 bug 与安全风险",
      "model": "claude-sonnet-4",
      "systemPrompt": "你是代码审查专家，只输出问题列表与证据。",
      "abilities": ["code_review", "file_access"],
      "lifecycleHooks": {
        "onStart": "collect-diff-context",
        "onEnd": "summarize-findings"
      }
    }
  }
}
```

## 五、委托边界设计（核心）
每个 Subagent 至少明确四件事：
- 任务输入：接收哪些上下文、文件范围、目标约束
- 任务输出：必须返回什么格式（结论、证据、建议）
- 禁止行为：不可修改什么、不可访问什么、不可执行什么
- 失败策略：失败后返回什么、是否重试、何时回退主流程

建议写法：
- "只读模式，禁止写文件与执行发布命令"
- "仅扫描 `src/payments/**`，忽略其他目录"
- "输出必须带文件路径与行号"

## 六、System Prompt 编写规范
建议包含：
- 角色：你是谁（专业能力）
- 目标：你要完成什么
- 约束：不可做什么
- 输出协议：固定结构、固定字段
- 终止条件：何时认为任务完成

反例：
- 目标不清："帮我看看代码"
- 输出不定："随便总结一下"
- 缺约束：允许任意改写导致越权

## 七、工具与权限策略
最小权限原则：
- 默认只读
- 默认无网络
- 只开放任务所需工具
- 对危险命令单独阻断

建议按任务类型分级：
- 审查类：`file_access(read)`、`search`
- 生成类：`file_access(write)`（限定路径）
- 运维类：需审批或专用受限执行器

## 八、生命周期与可观测
建议启用生命周期钩子：
- `onStart`：收集最小上下文、记录任务 id
- `onEnd`：统一输出摘要、结构化结果、失败原因

建议记录：
- subagent 名称、输入摘要、输出摘要
- 执行时长、调用次数、错误类型
- 是否触发回退

## 九、多 Agent 协作模式
常见模式：
- Sequential：A -> B -> C
- Hub-and-Spoke：主代理调度多个 Subagent
- Hierarchical：上层分解、下层执行

建议默认：
- 先 Sequential 验证稳定性
- 再扩展到并发 Hub-and-Spoke

## 十、与 Skill 的关系
- Skill 定义可复用能力单元
- Subagent 是 Skill 运行时的委托机制
- Skill 文档中应说明：何时委托、委托给谁、期望输出

示例（写入 SKILL.md）：
- 当输入是大规模变更（>500 行）时，先委托 `code-reviewer` 进行风险筛查。
- 若筛查失败或超时，回退为主流程最小检查。

## 十一、检查清单
- [ ] 委托边界明确（输入/输出/禁止行为/失败策略）
- [ ] system prompt 包含角色、目标、约束、输出协议
- [ ] 工具权限最小化并与任务匹配
- [ ] 生命周期钩子定义完整（如适用）
- [ ] 输出可追溯（含证据与定位）
- [ ] 失败时有明确回退路径
